二、性能优化案例：矩阵乘法

1. 基本实现

矩阵乘法定义：
[
C = A \times B, \quad c_{ij} = \sum_{k=1}^{n} a_{ik}b_{kj}
]

在三种语言中实现该算法的运行性能差异显著：

语言 特点 性能原因
Python 解释执行 每条语句需动态解析、对象创建与销毁
Java 字节码 + JIT 优化 运行时可即时编译热点代码
C语言 直接编译成机器码 静态编译执行最快

💡 结论：解释型语言慢，编译型语言快；但JVM的JIT优化在部分场景下甚至可超越未优化的C程序。

3. 编译器优化级别

C 编译器的常见优化选项：

参数 含义
-O0 不优化（调试模式）
-O1 基础优化
-O2 启用大多数优化（推荐默认）
-O3 激进优化（循环展开、向量化）

不同编译选项对性能影响可达数十倍。

5. 循环分块（Loop Blocking / Tiling）

思想

将矩阵拆分为多个小块，使得每块可完全装入缓存，从而减少主存访问次数。

未分块：

  • 每次写入整行 C，缓存不断被替换。
  • 访问内存约 128 MiB。

分块后（如 64×64）：

  • 每次处理一个小块；
  • 访问内存仅约 4 MiB。

优点

  • 提高缓存命中率；
  • 显著提升内存带宽利用率；
  • 是矩阵乘法性能优化的核心手段。

6. 多级缓存优化 + 向量化

  • 二级分块：针对 L1/L2/L3 缓存的不同容量设计不同 block size；

  • SIMD 向量化：使用 AVX/AVX2/AVX-512 指令；

  • 对 4096×4096 矩阵乘法，性能可提升 超过五万倍。

7. 思考与实践方向

  • 何时循环交换反而无效或降低性能？
  • 并行线程数增加是否总是提高性能？
  • 如何确定最优分块大小？
  • 使用 AVX-512 是否一定快于 AVX2？
  • 能否建立性能与参数（block size、线程数、cache）的数学模型？

软件系统优化笔记 · 第二章：性能测量

一、性能测量方法

方法 说明 工具示例
外部测量 通过系统级工具观测性能 time、perf
内部测量 在代码中插入计时器（插桩） clock_gettime()
仿真测量 用仿真器模拟系统行为 Valgrind、Cachegrind

二、常见计时器

API / 指令 精度 特性
clock_gettime(CLOCK_MONOTONIC) ns 推荐使用，单调递增
gettimeofday() μs 受时区与系统时间影响
rdtsc CPU周期 非统一跨核，不推荐通用场景

三、性能数据收集策略

策略 特点 工具
计数型 统计事件总次数 perf stat
采样型 定期采样系统状态 perf record / report
追踪型 记录事件时间序列 strace, bpftrace

1. 计数型（Counting）

输出：

计算 IPC（每时钟周期平均指令数）。

2. 采样型（Sampling）

用于识别热点函数与指令。
设置采样频率为 99Hz 可避免与系统时钟重叠造成偏差。

3. 追踪型（Tracing）

输出系统调用序列、时间戳、参数和返回值。
适用于系统调用瓶颈分析。

四、性能波动与系统静默

性能波动来源

  • 软件层面：后台任务、中断、调度、多租户、数据对齐
  • 硬件层面：超线程（HT）、睿频（Turbo Boost）、DVFS、网络负载

控制方法（系统静默）

  • 固定线程绑定（taskset、numactl）
  • 关闭后台任务和节能机制
  • 禁用 HT / Turbo / DVFS

经控制后，85% 的实验结果可稳定在 ±3% 误差范围。

五、误差与精度

  • 随机误差：由系统波动引起，可通过多次取平均减少；
  • 系统误差：由测量方法本身引入；
  • 分辨率与精度：高精度计时器可减少量化误差。

软件系统优化笔记 · 第三章：基准评测

一、基准评测的意义

基准评测（Benchmarking）用于：

  • 量化系统性能差异
  • 比较不同硬件/软件实现
  • 指导优化与选型

二、基准评测程序类型

类型 说明 示例
单一指令 测试单个操作的性能 ADD
指令组合 模拟真实负载的指令分布 IBM 704
合成程序 模拟特定工作负载 Dhrystone
程序内核 代表常见计算模式 矩阵乘法、排序
微基准 评测系统局部组件 JMH、LMbench
应用基准 真实应用集合 SPEC CPU、TPC-C

三、标准化基准套件（SPEC）

SPEC CPU 2017

  • 43个C/C++/Fortran程序；

  • 模式：

    • Speed：单实例可多线程；
    • Rate：多实例单线程；

  • 输出指标：

    • 执行时间；
    • 吞吐率。

四、基准评测策略

策略类型 定义 示例
固定计算量 任务量固定，测执行时间 SPECspeed
固定时间 时间固定，测完成度 SLALOM
可变计算与时间 同时考虑质量与速度 HINT

五、两条经典定律

阿姆达尔定律（Amdahl’s Law）

当程序中可并行部分占比 ( p )，使用 ( n ) 个处理器时：
[
Speedup = \frac{1}{(1-p) + \frac{p}{n}}
]
限制：串行部分越大，整体加速越受限。

古斯塔夫森定律（Gustafson’s Law）

若问题规模可随处理器数扩展：
[
Speedup \approx p
]
启示：应扩大工作负载以充分利用资源。

六、小结

  • 基准评测提供了标准化性能比较基础；
  • 选择基准应贴近真实负载且结果可复现；
  • 固定计算、固定时间、可变计算三种策略适用于不同场景；
  • 阿姆达尔定律体现上限，古斯塔夫森定律体现扩展潜力。
